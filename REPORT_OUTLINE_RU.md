# Конспект для доклада (готовый текст‑скелет)

## 1. Цель работы
Реализовать мультиагентную систему (MAS), моделирующую работу такси в городе.  
Цель симуляции — показать взаимодействие агентов (водители, заявки, диспетчер) и влияние стратегии матчинга на метрики: ожидание, отмены, загрузку и доход.

## 2. Среда (Environment)
Город — клеточная сетка W×H.  
За 1 такт водитель делает 1 шаг по Манхэттену.  
Расстояние: d(a,b)=|x_a-x_b|+|y_a-y_b|.

## 3. Агенты

### 3.1 Driver
Состояния: idle / to_pickup / on_trip.  
Поведение: едет к origin → забирает → едет к dest → завершает, зарабатывает цену поездки.  
Дополнительно: ребалансировка в “горячую” зону спроса.

### 3.2 Request (Passenger)
Поля: origin, dest, created_at, patience.  
Отмена: если не назначена и (t-created_at)>patience → canceled.

### 3.3 Dispatcher
Делает matching раз в N тактов.  
Цена: base_fare + per_step_fare*distance, умноженная на surge.  
Surge зависит от спрос/предложение.

## 4. Протокол MAS
1) Генерация заявок по Poisson(λ).  
2) Диспетчер назначает пары водитель‑заявка.  
3) Водители перемещаются и выполняют поездки.  
4) Метрики собираются автоматически.

## 5. Стратегии матчинга

### 5.1 Greedy
Назначаем ближайшего водителя для каждой заявки (в порядке появления).

### 5.2 Auction
Для каждой заявки водители оценивают “стоимость”:
cost = alpha*pickup_distance + beta*trip_distance (+ небольшой шум).  
Диспетчер назначает пары, избегая конфликтов 1 водитель → 2 заявки.

## 6. Метрики
avg_wait, p95_wait, cancel_rate, avg_driver_util, avg_driver_income.

## 7. Эксперименты
Сравнить greedy vs auction при одинаковом seed, меняя request_rate и n_drivers.

## 8. Выводы
MAS позволяет гибко менять поведение и стратегии, измеряя результат метриками и графиками.
